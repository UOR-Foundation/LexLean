# mathlib-blake3-g

The acceptance demo of the Mathlib import (issue #340): four modules that prove, for every 32-bit word, what the BLAKE3-in-LexLean work could only test, citing lemmas of Lean core and Mathlib through a generated glossary.

- **Language:** 1.2, with `[[lean_library]] mathlib` pinned at `520045ab14e2` (Lean `v4.32.1`). **Source modules:** 4 under `src/`.
- **Proved** (`BitVec 32`; the first two also at `UInt32`): `(a + b) - b = a`; `(a ^^^ b) ^^^ b = a`; `rotl (rotr a n) n = a` for n in {7, 8, 12, 16}; and that the eight-step inverse of the BLAKE3 G function recovers `a b c d` from its output and the message words `x y`, as a relation between the 22 words.
- **Glossary.** `glossary/lean.mathlib` is generated by `lexlean deps glossary` from the host modules `Blake3GHost` and `Blake3GSpecs` and is never edited. `Blake3GSpecs.lean` is emitted from `wrappers.toml` (`cargo xtask emit-wrappers`): specialisations at `BitVec 32` and `UInt32` of the lemmas cited. `glossary/blake3.g` holds label words for titles and headings, nothing else.
- **What is not imported.** `rotateLeft (rotateRight x n) n = x` is in neither Lean core nor Mathlib at this pin. `Blake3GHost.lean` proves it in ordinary Lean (axioms `propext`, `Quot.sound`); it is a lemma of this project's host library, not of an imported library.
- **A demo, not an example.** It needs a fetched library, so it lives under `demos/` and the default sweeps of `examples/` never see it (`EX-10`). Register rows whose gates it exercises (`model/ids.toml`, level `build`): `EX-10`, `ML-01` to `ML-05` (the library is declared, locked and never fetched by `verify`), `VR-25` and `VR-26` (imported declarations in the attestation), `VR-27` (how the probe writes generated signatures).
- **What is claimed.** `cargo xtask verify-demos` formats, locks, checks, builds and verifies the project (elaboration, `leanchecker` replay of the project's modules, exact axiom audit) and compares with `expected/`. Nothing about the proofs of Mathlib or of Lean core: they are imported, replayed in the pinned environment, not proved here (SPEC.md §4.2, §5.3).
- **Needs the library.** The example fails with `LLV7019` unless `.lake/packages/mathlib` is the pinned checkout with built artifacts. `./setup-offline.sh` hard-links an existing checkout (`MATHLIB=~/mathlib-pinned`) and builds the host library; `lexlean deps fetch` acquires it otherwise. `.lake/` is not tracked.
- **Run.** `./setup-offline.sh`, then `lexlean check` and `lexlean verify` here. The comparison with `expected/` is `cargo xtask verify-demos` from the repository root, which `.github/workflows/mathlib.yml` runs after `lexlean deps fetch` (about 5 minutes and 7 GB; no build cache).
